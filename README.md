# TasCorp — автотесты (Appium + pytest)

Один проект, две сборки: **TasCorp UZ** и **TasCorp KZ** (Android). Экраны и общая механика
интерфейса одинаковые, но состав полей и справочников в заявке — разный, это требования
закона каждой страны. Поэтому общий только UI-слой и конфигурация (APK, package/activity,
менеджер), а бизнес-логика заявки у каждой страны своя и физически лежит в своей папке.
См. «Архитектура: несколько сборок» ниже.

**iOS-платформа** — отдельный проект в папке [`ios/`](ios/README.md): свой код, локаторы,
сценарии, conftest и Appium (порт 4724), ни одного общего файла с Android-тестами ниже.
В админке Android и iOS разделены переключателем платформы.

## Подготовка (один раз)
```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
appium driver install uiautomator2   # если ещё не установлен
```
Положить APK: `apks/uz/TasCorpUzTest.apk` (уже есть), `apks/kz/TasCorpKzTest.apk` (когда появится).

## Запуск
1. Запустить эмулятор `Autotest_API_34` (Android 14, без Play Store — быстрее):
   `~/Library/Android/sdk/emulator/emulator -avd Autotest_API_34 -no-boot-anim -no-audio -gpu host`
   Проверить: `adb devices`
2. В отдельном терминале: `appium`
3. `.venv/bin/pytest` — все сборки сразу, или `.venv/bin/pytest tests/uz` / `tests/kz` — одна.

При падении теста скриншот сохраняется в `screenshots/<имя_теста>_failed.png`
(при запуске из админки — в папку запуска `reports/<запуск>/screenshots/`).

Переменные окружения: `APPIUM_URL`, `DEVICE_NAME`, `MJPEG_PORT` — общие;
`UZ_APK_PATH`/`KZ_APK_PATH` и `UZ_MANAGER_LOGIN`/`PASSWORD`/`PIN`, `KZ_MANAGER_...` — по сборкам
(см. `tests/projects/uz.py`, `tests/projects/kz.py`).

Логины и пароли менеджеров в коде не хранятся: скопируйте `.env.example` в `.env` в корне
репозитория и заполните (`.env` в git не попадает). Без них тесты падают с подсказкой.

## Админка (запуск тестов из браузера)
```bash
./run_admin.sh          # поднимет Appium, если он не запущен, и откроет сервер
```
Открыть http://127.0.0.1:5050 — вкладки **Все / TasCorp UZ / TasCorp KZ** переключают,
кейсы какой сборки видны в списке. Отметить нужные чекбоксами и нажать «Запустить выбранные» —
запустятся только они, можно выбрать кейсы сразу из разных сборок за один прогон.
Статусы обновляются в реальном времени, есть лог и история запусков (`reports/`).

Блок «Экран устройства» — живая трансляция экрана эмулятора во время теста (MJPEG от UiAutomator2,
порт `MJPEG_PORT`, по умолчанию 9100). Скриншот сохраняется только при падении кейса —
он виден в «Подробностях ошибки» и лежит в `reports/<запуск>/screenshots/`.

Новый кейс появляется в админке автоматически — достаточно добавить функцию `test_*` в
`tests/uz/` или `tests/kz/`. Название кейса берётся из первой строки docstring (или из
маркера `@pytest.mark.title("...")`), вкладка — из папки (`tests/<uz|kz>/...`):
```python
def test_login_opens(driver, manager):
    """Авторизация: по кнопке «Kirish» открывается экран входа"""
```

### Management: кейсы агента по задачам спринта
http://127.0.0.1:5050/management — задачи спринта из Azure Boards (`tasfinance/FC`, команда
`MobApp TasCredit`). Агент (Claude Code через соседний проект `../tascorp-testgen`) анализирует
требования задачи и пишет тест-кейсы, регресс-кейсы и открытые вопросы к PM. Кейсы хранятся
локально (`admin/management.db`) и попадают в Qase (проект `TM`, статус Actual) **только после
подтверждения**: кнопка «Подтвердить» у кейса или «Подтвердить все». Неподходящий кейс можно
поправить ✏️ или отклонить с причиной.

- «Сгенерировать кейсы» — вручную по любой задаче (≈2 мин и ≈$0.4 на задачу).
- Переключатель «Автогенерация» — агент раз в `MGMT_POLL_MIN` минут (10) проверяет текущий спринт
  и сам берёт задачи в статусах `MGMT_AUTO_STATES` (`Active`), по которым кейсов ещё нет.
- «Требование изменилось» — описание задачи в Azure поменялось после генерации; «Перегенерировать»
  заменит только неподтверждённые кейсы.
- Токены и проекты — в `../tascorp-testgen/.env`; качество кейсов — `prompt.md` и `product_context.md` там же.

## Архитектура: несколько сборок

**Правило.** У каждой сборки (страны) — свой, полностью независимый код: свои Page Object'ы,
свои локаторы и экранные тексты, свои сценарии, свои тестовые данные. Никакого общего слоя
UI-механики между странами нет — даже если два экрана выглядят и работают одинаково, каждая
страна держит собственную копию. Правка/добавление теста в `tests/uz/` не может затронуть ни
одной строки в `tests/kz/`, и наоборот. Единственное, что переиспользуется — это `pages/base_page.py`
(`BasePage`, `wait_visible`, `tap`, `by_text`/`by_test_id`): это не локаторы и не текст экрана,
а обвязка над Appium/Selenium (общая для любого Android-приложения, не только TasCorp),
плюс `tests/conftest.py` (сборка сессии Appium из `Project`) и `factories_common.py`
(генераторы строк/дат без домена: `digits`, `letters`, `random_day`).

```
tests/
  pages/
    base_page.py          — BasePage + by_text/by_test_id: обвязка над Appium, без локаторов приложения
  conftest.py              — fixture `driver` (capabilities из fixture `project`), `manager` = project.manager
  factories_common.py      — универсальные генераторы (digits/letters/random_day), без домена
  projects/                — техданные сборок: APK, package/activity, менеджер
    base.py                  Project/User (dataclass) + Project.apk_path
    uz.py, kz.py              по одному файлу на сборку — весь дифф между странами тут

  # каждая страна — независимый пакет, ничего не делит с другой страной
  uz/
    conftest.py             fixture `project` = projects.uz.PROJECT
    pages/                   Page Object'ы экранов UZ: старт («Kirish»), логин, код, главная
                             («asosiy»/«Arizalar»), меню/настройки/язык, список заявок,
                             компоненты форм (components.py: поля по подписи, справочники,
                             системный календарь, камера)
    flows.py                 login(), switch_to_russian() — сквозные шаги по экранам UZ
    application_wizard.py    шаги мастера заявки UZ (ПИНФЛ, область/район, орган выдачи — закон UZ)
    factories.py             случайные данные под форматы UZ
    scenarios.py             все кейсы UZ: запуск, вход, смена языка, create_application_*
    test_launch.py, test_auth.py, test_settings.py, test_application.py — тонкие обёртки над scenarios.py
  kz/                        то же самое устройство, полностью свой код:
    conftest.py             fixture `project` = projects.kz.PROJECT
    pages/                   старт («Кіру» — кириллица, не путать с латинским "Kipy"), логин,
                             код, главная («бастапқы бет»/«Өтінімдер»)
    flows.py                 login() — сквозные шаги по экранам KZ
    scenarios.py             app_opens_first_screen, manager_login (заявка ещё не реализована)
    test_launch.py, test_auth.py — обёртки над kz/scenarios.py
```
**Добавление новой сборки** (например, третьей страны): файл `tests/projects/xx.py` с
`Project(...)`, папка `tests/xx/` с собственными `conftest.py`, `pages/`, `flows.py`,
`scenarios.py` — по образцу `tests/uz/` или `tests/kz/`, без единой правки в файлах других стран.

**Если APK сборки нет на месте** (например, `apks/kz/` ещё пуст) — её кейсы всё равно видны
в админке, но при запуске получают понятный `skip` с объяснением, а не ошибку Appium.

Кейсы (набор пока отличается по сборкам — у KZ реализованы только запуск и авторизация):
| Файл | Кейсы | UZ | KZ |
|---|---|---|---|
| `test_launch.py` | Запуск приложения, стартовый экран | ✅ | ✅ |
| `test_auth.py` | Авторизация менеджера (логин/пароль + код 2222) | ✅ | ✅ |
| `test_settings.py` | Смена языка на русский (меню → Настройки → Язык) | ✅ | — |
| `test_application.py` | Создание заявки «Новая»: базовая / с доп. фото / с доп. фото и созаёмщиком | ✅ | — |

- `tests/uz/factories.py` — случайные данные UZ: ПИНФЛ (14 цифр), серия (2 буквы), номер (7 цифр),
  ГРНЗ (`323FFM05`), техпаспорт (3 буквы + 7 цифр), даты (возраст 21–35, документ действует ≥ 10 лет).
- Каждый тест стартует с чистого состояния приложения (данные сбрасываются между сессиями).
- Тесты заявок **создают реальные заявки** на стенде (видны во вкладке «На оценке»).

### Краш KZ на эмуляторе (не блокирует тесты)
При запуске сборки TasCorp KZ под Appium/UiAutomator2 иногда (не всегда, момент плавает —
от 2 до 10 секунд после старта) вылетает:
```
FATAL EXCEPTION: main
java.lang.AssertionError: setLocale() should be called before initialize()!
    at com.yandex.mapkit.MapKitFactory.setLocale(MapKitFactory.java:48)
    at ru.vvdev.yamap.RNYamapModule.setLocale$lambda$1(RNYamapModule.kt:58)
```
Баг в порядке инициализации `react-native-yamap` (`setLocale()` вызывается после
`MapKitFactory.initialize()`). Проверено: при обычном запуске через `adb shell am start`
(без подключения Appium/UiAutomator2) приложение не падает 25+ секунд — краш коррелирует
именно с подключением инструментария Appium к процессу на эмуляторе. На реальном устройстве,
по данным команды, не воспроизводится вовсе. `test_launch.py`/`test_auth.py` для KZ проходят
стабильно (4/4 подряд на момент написания), но это не доказывает отсутствие гонки — краш
плавающий, стоит присматривать за стабильностью при последующих прогонах, а окончательно
статус бага подтвердит прогон на реальном телефоне.

### Особенности приложения, учтённые в тестах
- Формы открыты в bottom-sheet: `driver.hide_keyboard()` и свайп вниз его закрывают.
  Клавиатура прячется тапом по подписи поля, форма заполняется строго сверху вниз.
- Экранная клавиатура на эмуляторе отключена (`no_soft_keyboard` fixture) — иначе Gboard
  принимал жесты прокрутки формы за ввод текста.
- Системный DatePicker: список годов листается медленным жестом без инерции с проверкой,
  что список остановился, иначе тап по году промахивается.
- Фото делаются системной камерой эмулятора (виртуальная сцена); кнопка съёмки и «Сохранить»
  нажимаются с повтором, пока камера/загрузка фото не готовы.

## Проверка стабильности
```bash
./scripts/stability.sh      # 7 полных прогонов подряд (по умолчанию все сборки), стоп на первом падении
./scripts/stability.sh 3    # 3 прогона
```
Логи и скриншоты падений — в `reports/stability/<время>/`. Перед каждым прогоном скрипт
проверяет, что эмулятор и Appium отвечают (иначе пишет `ENV FAIL`, а не падение теста).

На Mac с 8 ГБ памяти эмулятору (3 ГБ) может не хватать RAM: при заполненном swap он
зависает. На время прогонов лучше закрыть тяжёлые программы (браузер, мессенджеры).
