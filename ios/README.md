# TasCorp — автотесты iOS (Appium XCUITest + pytest, iOS Simulator)

Отдельный проект для iOS-платформы. С Android-автотестами (`tests/`, `apks/`, `scripts/`
в корне) не делит **ни одного файла**: свои Page Object'ы, локаторы, сценарии, тестовые
данные, conftest, `pytest.ini`, Appium-сервер. Общее у платформ только админка и `.venv`.

Приложение то же самое (React Native), поэтому кейсы и их названия повторяют Android-версию,
но реализация под XCUITest своя — правка iOS-теста не может сломать Android, и наоборот.

```
ios/
  pytest.ini                — testpaths = tests, pythonpath = tests
  tests/
    conftest.py             — сессия XCUITest, Simulator, тестовая камера, скриншоты падений
    projects/base.py, kz.py — техданные сборки: .app, bundle id, менеджер
    pages/base_page.py      — обвязка над Appium для iOS: ожидания, by_name/button/static_text
    factories_common.py     — генераторы строк/дат
    kz/
      locators.py           — ВСЕ локаторы сборки по экранам (Login, IdCard, Car, ExtraData…),
                              у каждого поля и кнопки свой
      pages/                — экраны (вход, главная, меню, «Заявки») и components.py —
                              действия с полями: ввод, справочник, дата, камера
      application_wizard.py — шаги мастера заявки: метод на каждое поле/справочник
      flows.py, scenarios.py, factories.py, test_*.py
  apps/kz/TasCorp.app       — сборка для Simulator (scripts/build_app.sh)
  scripts/
    build_app.sh            — скачать актуальный IPA со стенда и перепаковать под Simulator
    sim_setup.sh            — создать Simulator «Autotest iPhone 15», английская раскладка
    appium.sh               — Appium для iOS на порту 4724
  tools/test_camera/        — тестовая камера для Simulator (у Simulator нет камеры)
```

## Подготовка (один раз)
1. **Xcode** в `/Applications` (на macOS 13 — максимум Xcode 15.2). Активировать через
   `xcode-select` не обязательно: скрипты используют `DEVELOPER_DIR`.
2. **Runtime iOS 17.2.** `xcodebuild -downloadPlatform iOS` в сети компании обрывается —
   надёжнее скачать `iOS_17.2_Simulator_Runtime.dmg` в браузере
   (https://developer.apple.com/download/all/, вход по Apple ID) и установить:
   `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun simctl runtime add ~/Downloads/iOS_17.2_Simulator_Runtime.dmg`
3. **Appium-драйвер xcuitest** — в отдельный `~/.appium-ios` (общий `~/.appium` частично
   принадлежит root, и npm не может туда ставить без sudo; Android-драйвер не трогаем):
   `APPIUM_HOME=~/.appium-ios npm_config_cache=/tmp/npm-ios appium driver install xcuitest@7.13.0`
   (7.13.0 — последняя версия под установленный Appium 2.5.2).
4. `ios/scripts/sim_setup.sh` — Simulator; `ios/scripts/build_app.sh` — сборка;
   `ios/tools/test_camera/build.sh` — тестовая камера.

## Запуск
- Из админки: `./run_admin.sh` (поднимет и Android-, и iOS-Appium) → переключатель **iOS**.
- Вручную: `ios/scripts/appium.sh` в отдельном терминале, затем
  `cd ios && ../.venv/bin/pytest` (или `../.venv/bin/pytest tests/kz/test_application.py`).

Первая сессия собирает WebDriverAgent — несколько минут. На Mac с 8 ГБ Android-эмулятор
и Simulator вместе не помещаются в память — перед iOS-прогоном эмулятор лучше остановить
(`adb emu kill`); админка и так запускает кейсы только одной платформы за раз.

Скриншот упавшего кейса — `ios/screenshots/` (из админки — в папке запуска `reports/<запуск>/`).

## Сборка приложения
Стенд раздаёт только Enterprise-IPA для iPhone (https://tascorp-admincp.tascredit.kz/res/test.html):
бинарник под платформу iphoneos Simulator не ставит. Исходников у нас нет, поэтому
`build_app.sh` перепаковывает IPA: у всех Mach-O платформа в `LC_BUILD_VERSION` меняется на
iOS Simulator (7), Enterprise-подпись заменяется ad-hoc. Архитектура та же (arm64) — работает
только на Mac с Apple Silicon. Новая сборка на стенде → просто перезапустить скрипт.

## Тестовая камера
У iOS Simulator нет камеры: кнопка съёмки системного экрана камеры неактивна, а без фото
заявку не отправить. Приложение снимает только камерой (галереи нет).

`tools/test_camera/TasTestCamera.dylib` подгружается в приложение **только в автотестах**
(`DYLD_INSERT_LIBRARIES` через `appium:processArguments`, см. `tests/conftest.py`); бинарник
приложения не меняется. Когда приложение открывает системную камеру (UIImagePickerController),
поверх неё ставится свой слой штатным API пикера: кнопка затвора `PhotoCapture` (тот же
идентификатор, что у системной) и `Cancel`. Затвор отдаёт приложению снимок через обычный
делегат пикера — дальше приложение обрабатывает и отправляет его как фото с камеры.

Снимок — картинка с подписью «TasCorp autotest», именем теста, номером снимка и временем
(видно в заявке, каким прогоном сделано фото). Свои картинки: папка в `TAS_TEST_CAMERA_DIR`.

Не проверяется: сам системный экран камеры, запрос разрешения на камеру, особенности снимков
настоящей камеры iPhone — это только на реальном устройстве.

## Скорость
«Новая заявка» — ~1,5 мин (до 2 мин, если сценарию приходится заново входить и менять язык).
Что для этого сделано — не возвращать при правках:
- Только нативные локаторы (class chain / predicate, ~0,2 с). XPath на iOS — 0,5–6 с на запрос.
- Ввод с `\n` в конце: Return закрывает клавиатуру той же командой (и у цифровых полей).
- Без предварительной прокрутки: ввод и тап сразу по элементу, XCUITest сам доводит его до
  экрана; свайп — только запасной вариант. `mobile: scroll` (scrollToVisible) — 10 с, не использовать.
- Справочник: случайный пункт по номеру (1–8) одним запросом, все пункты разом не запрашивать
  (у марок ~150 — 20 с); фильтр `wdVisible` у этого списка не работает.
- Значения на сводке читаются из дерева без прокрутки.
- `waitForQuiescence: false`, `animationCoolOffTimeout: 0`, `maxTypingFrequency: 300`. Цена:
  поле, выезжающее анимацией, ждём явно (`wait_still`) — иначе ввод теряется (экран логина).

## Особенности приложения на iOS, учтённые в тестах
- Пароль в защищённое поле доходит целиком только при **английской раскладке** Simulator
  (с русской XCUITest вводил половину символов). Раскладку выставляет conftest перед сессией.
- Клавиатура на экране логина закрывает «Кіру» и не прячется тапом по подписи — «Готово».
  В формах заявки клавиатура прячется тапом по подписи поля.
- Скриншоты через WDA не показывают защищённые поля и клавиатуру — смотреть через
  `xcrun simctl io booted screenshot`.
- В React Native контейнеры перенимают подписи дочерних элементов — элемент по имени берётся
  последний (самый глубокий), см. `pages/base_page.by_name`.
- Поле ищется по группе «<подпись> <подсказка/значение>» (`locators.text_field`): контейнер
  самого поля назван подсказкой и после ввода переименовывается в значение. «Тип займа»
  (недоступное поле) в дереве стоит последним — у него свой локатор.
- Даты — колёса UIDatePicker (месяцы по-английски); выбранная дата в дереве доступности не
  видна (у кнопки пустой label) — проверяется на экране-сводке.
- После закрытия клавиатуры/шторки форма ещё сдвигается: тапы по дате и «Добавить фото
  документа» — с ожиданием остановки и повтором.
- Кнопка ⟳ у «Сделка в bitrix» без подписи; у тестового менеджера в списке сделок только «#».
- Карточка заявки в приложении менеджера фото не показывает — проверять фото в веб-админке.
